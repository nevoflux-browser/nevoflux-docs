title: 远程控制
description: 用手机驱动你的 NevoFlux 会话、让手机配对后跨重启保持可用,或让另一个 AI 智能体使用你的浏览器并把整项任务交给 NevoFlux 执行 —— 全部经由端到端加密通道。已更新至 agent v0.3.16。
---

远程控制让*不在*你电脑前的东西,也能与这台电脑上运行的 NevoFlux 协作。对话、浏览器、
工具以及权限提示都留在你的机器上;远程的只是向它输入、观看它工作的那一端。

> **这是*同一个*会话,而不是第二个。** 手机永远不会获得自己的智能体。它是在你电脑上
> 已存在的对话中输入,并看到那段对话产生的一切。

共有三种接入方式,区别在于持续多久、以及另一端是谁:

| 命令 | 谁来连接 | 持续多久 | 起始版本 |
| --- | --- | --- | --- |
| `/remote-control` | 手机(或任意浏览器),连到**一个**会话 | 直到该会话窗口关闭 | v0.3.13 |
| `/pair-device` | 手机,连到这台机器上的**所有**会话 | 直到你解除配对 —— 重启后依然有效 | **v0.3.16** |
| `/pair-agent` | 另一个 **AI 智能体**(首个客户端:Muse),通过 MCP | 直到你解除配对 —— 重启后依然有效 | **v0.3.16** |

这三条命令都在侧边栏中输入,也都列在 `/` 菜单里。它们都要求这台机器已登录
nevoflux.app 账号,而另一端必须登录**同一个**账号 —— 中继会拒绝其他任何人。

## 登录

第一次运行 `/remote-control` 时,智能体会发起设备登录:它会打开 nevoflux.app 的批准
页面,并已填好设备码。如果页面要求登录就先登录(设备码在登录后仍会保留),然后点击
**Approve**,智能体会自行继续。它最多等待 30 分钟。

`/pair-device` 和 `/pair-agent` 本身不会发起登录。如果机器尚未登录,或登录已过期,
它们会直接告诉你 —— 先运行一次 `/remote-control` 完成登录,再重新运行它们。

## 打开单个会话:`/remote-control`

在你想交出去的那段对话中输入:

```text
/remote-control
```

登录之后,它会回复一个连接链接和一个配对码:

```text
✅ Remote control is open.

On the other device, open this link and sign in to the same account:
https://portal.nevoflux.app/connect/<channel-id>

Then enter the pairing code:
  <配对码>
```

在手机上打开该链接、登录、输入配对码,手机就连上了那段对话。

这是轻量的方式:什么都不会被记住。关闭窗口即终止通道;重启之后,手机停留在一个这台
机器再也不会拨回的通道上。适合"我离开一小时"的场景;想长期使用的手机请用
`/pair-device`。

对话模式与 [Agent execution 档位](/zh/docs/settings/general#agent-execution-权限档位)
会在 `/remote-control` 运行时从侧边栏快照下来,所有远程轮次原样继承。手机会*显示*这
两项,但两项都无法更改 —— 所以如果你打算离开电脑,请在运行命令**之前**先选好档位。

## 配对手机:`/pair-device`

*v0.3.16 新增。*

```text
/pair-device
```

侧边栏会显示一个二维码、它所编码的链接(`https://portal.nevoflux.app/d/<id>/pair`)
以及一个配对码。然后在手机上:

1. 扫描二维码,或打开该链接。
2. **在 iPhone 上,先把它添加到主屏幕**,再从主屏幕打开。主屏幕应用与 Safari 的存储
   是分开的,在 Safari 里完成的配对,主屏幕应用一无所知。(iPhone 上的通知也只能在
   主屏幕应用中使用。)
3. 输入配对码,并可选地为这台机器起个名字。

二维码只包含链接,**绝不**包含配对码。通道密钥正是由配对码派生的,让它远离 URL,
就让它远离浏览器历史和 referrer —— 这也意味着配对既需要拿到链接,又需要读到屏幕上的
内容。配对码只显示**一次**:机器保存的是由它派生出的密钥,因此没有任何东西可以再显示
一遍。如果你在输入之前就弄丢了它,请解除配对后重新配对。

此后配对在重启后依然有效。机器每次启动都会重新拨号连接它。

### 已配对的手机上能看到什么

手机应用会列出**这台机器上的所有会话**,等待你处理的排在最前,每个会话标注为
**Waiting**、**Plan**、**Running** 或 **Idle**:

- **直接在列表中回答。** 被权限提示阻塞的会话会显示与桌面对话框相同的问题,并带有
  **Allow** 和 **Deny** 按钮。这个回答与在桌面上回答会变成同一条消息,所以无论先在哪
  一端回答,该提示都只会被处理一次。
- **打开某个会话**即可在其中聊天。对话最近的部分会先重放 —— 包括你在电脑前输入的内容
  —— 让你在批准时看到上下文,而不只是一个孤立的问题。同一时间只显示一段对话;切换到
  另一段时,移动的是现有通道,而不是新开一个。
- **通知。** 启用通知后,当某个会话停下来询问你时,机器可以唤醒手机。推送由你的机器
  自己发出;其内容只包含会话 id 和问题类型,因为锁屏上的内容谁拿着手机都能看到。

已配对的手机获得的权限,恰好是**每个会话**本来就有的权限。打开某个会话时,该会话的
对话模式与执行档位会从桌面端针对该会话重新读取 —— 绝不会沿用你之前所看会话的设置 ——
因此手机无法通过切换会话来提升某个会话的权限。

如果列表一直为空,而应用提示机器有响应、但发来的内容都无法读取,说明配对码输错了:
请在桌面端解除配对后重新配对。

### 查看与撤销配对:`/devices`、`/unpair`

```text
/devices
/unpair <id>
```

`/devices` 会列出与这台机器配对的所有手机和智能体,附带一个 8 位短 id、配对时间,
对于手机还会显示它是否还能被唤醒("cannot be woken" 意味着它的通知已悄然失效)。
`/unpair <id>` 接受这个短 id(只要不产生歧义,前缀即可),并撤销配对:关闭其通道、
删除其密钥,推送订阅也随之删除。重新配对需要新的配对码。

由于配对按设计会在重启后保留,**丢失或卖掉的手机在你解除配对之前,始终保有接入的
途径。** 请把 `/devices` 列入丢手机后的处理步骤。

## 手机能做什么

以下内容同时适用于 `/remote-control` 以及已配对手机上打开的会话。

| 在手机上 | 说明 |
| --- | --- |
| **发送一轮对话** | 进入同一段对话,并附带你本地的标签页上下文 |
| **实时观看** | 流式回复、思考过程、工具调用与制品都会实时呈现 |
| **停止生成** | 停止按钮映射到本地的停止 |
| **回答权限提示** | 工具批准会出现在手机上,可在手机上批准或拒绝 |
| **审阅计划** | 计划提案会像在本地一样送达等待批准 |
| **选择标签页**(`#`) | 指定本轮对话针对哪个已打开的标签页 |
| **提及某个灵魂**(`@`) | 把本轮对话路由到特定的 [Space Soul](/zh/docs/features/space-souls) |
| **调用技能**(`/`) | 输入框会列出你已安装的[技能](/zh/docs/skills) |
| **清空对话**(`/clear`) | *v0.3.14。* 一次性在所有地方清空该会话 —— 桌面、数据库以及手机自己保存的副本。它在守护进程处就被拦下,模型不会看到,并且会停止正在运行的轮次 |
| **发送原图** | *v0.3.14。* 勾选 **原图**(Original),除压缩版本外还会发送未经处理的原始文件(见下文) |
| **查看图片、收听与播放媒体** | *v0.3.14。* 截图、朗读的语音以及机器上的文件都能在手机上播放(见下文) |
| **接收通知** | 智能体在本地会通知你的内容都会转发过去 |

为了填充 `/`、`@` 和 `#` 菜单,手机可以向守护进程询问的内容**恰好只有三项** —— 技能
列表、灵魂列表和已打开标签页列表。这是一份**允许清单,而非过滤器**:没有任何其他命令能
经此通道到达守护进程,所以手机无法安装 pack、写入配置、碰触知识库,也无法更改任何
智能体配对。

## 图片、声音与文件

*v0.3.14 新增。*

- **截图以图片形式送达。** 智能体拍下的截图保存在你的机器上,手机按 id 拉取。模型依然
  能*看到*截图,但再也无法把图片字节写进回复 —— 以前手机上出现一大片无法读取的 base64,
  正是这个原因。
- **朗读在手机上播放。** 让智能体朗读某段内容,用本地 Kokoro 语音合成的声音(无需 API
  密钥,合成过程不离开本机)会在手机上播放,第一句准备好就开始,而不必等整段朗读完成。
- **播放机器上已有的文件。** 比如说"播放 ~/Videos/demo.mp4",智能体就会把这个文件提供
  给手机,由手机按需流式拉取,文件既不会被复制,也不会被读进对话。只提供媒体类型(常见的
  视频、音频与图片格式),并且需要与在你的执行档位下读取文件相同的权限 —— 询问时你看到
  的是解析后的实际路径。
- **发送原图。** 默认情况下手机发送的是压缩后的图片,这对大多数对话都合适。勾选
  **原图** 后,未经处理的原始文件也会经加密通道分块上传并保存在机器上,智能体可以用工具
  打开它查看全部细节,而模型拿到的是按其可见能力缩放的版本。机器不会轻信手机关于文件的
  任何说法:文件名由机器生成(你的文件名仅用于显示),大小与校验和会重新核对,类型则从
  文件自身的字节判断。上传的文件在连接中断时会保留(对话仍在讨论它们),在通道彻底结束
  时删除,超过一天的残留文件会在启动时清理。

媒体走一条独立的 socket,因此大文件永远不会堵住排在它后面的回复文字。

> **点对点传输与屏幕共享不在发行版构建中。** v0.3.15 新增了一条通往手机的 WebRTC 直连
> 路径(并支持 STUN/TURN,以连接处于移动网络后的手机),以及一个在请求录屏权限后实时
> 共享屏幕的 `screencast_start` 工具。两者只有在以 `webrtc` 特性构建 agent 时才会编译
> 进去,而 v0.3.16 的发行版二进制没有启用它。在发行版构建中,一切都经由中继传输 —— 中继
> 可以传送图片和文件,但无法传送实时流;要求智能体共享屏幕时会返回一条说明此情况的错误。

## 配对 AI 智能体:`/pair-agent`

*v0.3.16 新增。*

另一个 AI 智能体可以像手机一样与这台机器配对 —— 然后把你的 NevoFlux 浏览器当作它的
浏览器使用,并把整项任务交给 NevoFlux 执行。首个客户端是 **Muse**;任何实现了
NevoFlux 智能体通道协议(经加密中继承载的 MCP)的智能体都可以配对。

```text
/pair-agent
```

侧边栏会显示一个四行的配对块:

```text
NEVOFLUX_AGENT_PAIRING
relay: wss://relay.nevoflux.app
channel: <channel-id>
code: A-BCDE-FGHJ-KMNP
```

把整块内容复制并粘贴给该智能体(对 Muse 可以说类似"install the NevoFlux client and
pair with this"的话)。随后智能体会通过设备登录登入**你的** NevoFlux 账号,由你在
**nevoflux.app/device** 批准。配对块只显示一次;`/devices` 会列出这个配对,
`/unpair <id>` 可将其撤销。

> **只配对你信任的智能体。** 运行该智能体的人,就拥有该智能体所拥有的能力:在其档位内,
> 它可以操作你的浏览器 —— 包括你已登录的标签页 —— 并借助技能和 Canvas 执行任务。在
> `full-auto` 下,这意味着对这台电脑的完全访问。

### 已配对的智能体能在你的浏览器里做什么

每个智能体配对都有**自己的执行档位**,与全局的"Agent execution"设置相互独立 —— 提升
其中一个永远不会放宽另一个 —— 并且每个新配对都从 **`read-only`** 开始。档位是一道上限:
超出档位的调用会被立即拒绝,不会询问任何人。

| 档位 | 智能体可以做什么 |
| --- | --- |
| `read-only` | 打开任意网页,可以在新标签页中,也可以在你的某个标签页中(替换原有页面);读取你打开的任何标签页,包括已登录的(邮箱、网银);查看你打开了哪些标签页。点击和输入会被拒绝 |
| `browser-auto` | 还可以在任何页面(包括已登录的页面)上点击、输入、填写、滚动、按键和切换标签页 —— 你在那里能做的任何事:提交表单、发送消息、购买东西、删除数据 |
| `browser-auto-local-read` | 对智能体而言与 `browser-auto` 相同;额外的本地读取只对侧边栏有意义 |
| `full-auto` | 还可以把你 NevoFlux 工作区文件夹中的文件上传到网页 —— 这是唯一一个智能体能把你的本地文件发送到网站的档位,而且由智能体决定哪个文件发到哪里 |

用 `/agent-tier <id> <tier>`(使用 `/devices` 中的短 id),或在 **设置 → Muse**
(`nevoflux://settings/muse`)中修改。修改从智能体的下一次调用起生效。智能体发送的任何
内容都无法更改它自己的档位。

智能体在你浏览器中的工作方式:

- **它有自己的标签页。** 它的第一次导航会在后台打开一个标签页,之后除非指定其他标签页,
  否则都在那里工作。它只有在列出标签页之后,才能操作你的某个标签页,而列表会标明哪些
  标签页是它自己的。
- **只能打开 `http`/`https` 页面**(以及 `about:blank`)。`file:`、`nevoflux:`、
  `javascript:` 和 `data:` URL 都会被拒绝。
- **隐私窗口不可触及。** 它的标签页在普通窗口中打开,它无法操作隐私窗口中的标签页,
  展示给它的标签页列表也不包含隐私标签页。
- **批准请求交给智能体一方。** 当某条站点或 pack 规则要求确认一次调用时,问题会发给
  智能体的客户端(MCP elicitation),由运行该智能体的人在 60 秒内回答。没有"始终允许"
  —— 每个问题都单独询问。如果智能体的客户端不支持提问,这类调用会被拒绝。

### 委托任务

除了单次浏览器调用,已配对的智能体还可以把**一整项任务**交给 NevoFlux:一次完整的智能体
轮次,在侧边栏的一个后台会话中以 Agent 模式运行,可使用技能、Canvas,以及配对档位允许的
所有工具。智能体负责启动任务、跟进进度、回答批准请求,也可以取消任务;任务完成后,智能体
会拿到回复,以及一张反映任务产出的图片(Canvas,或任务所操作的标签页)。

配对档位是整项任务的边界,而不只是浏览器的边界:超出档位的工具会被立即拒绝,降低档位会
让下一次工具调用停下。由已配对智能体启动的会话始终以**该配对的**档位运行;修改该会话
自身的档位或你的全局默认值,都无法提升它。

**你在桌面上看到什么。** 已连接或已暂停的配对智能体会在侧边栏顶部各占一行,说明各自在做
什么("working: …"、"waiting for approval · 42 s left: …"、"connected · 12 min"),
并带有 **Pause** / **Resume** 和 **Unpair**(Unpair 需要再点一次确认)。正在运行的任务
会在其智能体下方显示一行,带有 **Stop task** 和 **View session**;后者会在侧边栏中打开
该任务的对话,你查看时会有一条横幅说明智能体正在处理它。

**任务中的批准请求** —— 权限提示、智能体自己提出的问题、待确认的计划 —— 可以在**任意
一端**回答:由智能体回答,或由你用任务那一行上的按钮回答。先回答者生效。任务批准请求会
保留 **30 分钟**;到期未回答即视为拒绝,任务失败。

**敏感操作总会询问,默认只有你能回答。** 在委托任务中,有十个工具无论档位如何 —— 即使是
`full-auto` —— 也无论此前是否允许过,都需要批准:安排定时工作、运行或恢复某个计划任务、
启动循环、切换 pack 或模型、设定目标、替换系统提示词,以及共享屏幕。默认情况下智能体
不能回答这些请求,它们会在桌面上等你处理。**设置 → Muse → "Let Muse approve sensitive
actions"** 可以让智能体也能回答(此时该行会显示"Muse may also answer")。

**NevoFlux 自身的设置受到保护 —— 但有限度。** 在委托任务中,智能体自带的文件写入工具会
拒绝写入 NevoFlux 配置或数据目录中的任何位置(`config.toml`、技能、pack、配对信息、
数据库)。Shell 命令以及 ACP 提供方自己的文件工具不受此限制,因此**在 `full-auto` 下这一
限制并不成立**:full-auto 就是完全访问,包括保存你设置与配对信息的那些文件。只把
`full-auto` 交给你愿意托付这台电脑的智能体。

**你当前的标签页不属于任务。** 委托轮次永远不会继承它所在会话的标签页上下文,因此你正在
看的页面不会泄露进由智能体控制的任务。

限制:每个配对同一时间只能有一项任务,每小时最多启动 20 次。如果你的模型提供方是一个 ACP
智能体,它永远不会同时运行一个委托轮次和一个你自己的轮次 —— 会告知对方提供方正忙。已完成
的任务可在一小时内(或在 NevoFlux 重启之前)取回结果;无论如何,其会话都会保留在你的
历史记录中。

### 暂停、恢复、解除配对

- **Pause(暂停)** 保留配对但关闭通道,在你点击 **Resume(恢复)** 之前,机器不会再次
  拨号连接它 —— 即使重启也不会。暂停会取消该智能体正在运行的任务。
- **Unpair(解除配对)** 会关闭通道、删除密钥、取消任务及所有未决问题,并忘记该智能体的
  标签页。

这两项都只能在本地操作:经中继到达的任何内容都无法暂停、恢复智能体或更改其档位。

## 安全模型

- **端到端加密。** 配对码与通道 id 通过 **Argon2id** 派生出一个 256 位密钥;帧使用
  **AES-256-GCM** 封装。中继只能看到密文 —— 它无法读取、伪造或篡改任何一帧,被伪造的帧
  会认证失败并被丢弃。智能体通道只接受加密封装的帧。
- **配对码就是那个秘密。** 通道 id 不可猜测,但并不保密 —— 拿到它的人可以接入并收到自己
  读不懂的密文。而拿到**配对码**(并登录了你账号)的人就能驱动你的会话。请像对待密码一样
  对待它,除了你正在配对的手机或智能体之外,不要粘贴到任何地方。
- **保存的密钥就在你的磁盘上。** 持久配对会把由配对码派生出的密钥(`pairings.json`、
  `agent-pairings.json`)保存在 agent 的数据目录中,与账号令牌放在一起。正因如此配对才能
  在重启后保留;这也意味着任何能读取该目录的东西 —— 包括 `full-auto` 下智能体自己的
  shell —— 都能读到它们。用 `/unpair` 撤销。
- **范围受限。** `/remote-control` 连上的手机只能看到它自己那段对话的事件,看不到其他会话。
  已配对的手机能看到会话列表以及它当前打开的那一段对话,并且只能打开列表中的会话。
- **谁来回答什么。** 手机上的提示由你回答。已配对智能体的单次调用批准由智能体一方回答。
  委托任务的批准请求两端都可以回答,但敏感操作除外 —— 除非你另行允许,它们只能由你回答。
- **不对外暴露任何服务。** 是守护进程主动向中继拨号;它不监听任何入站端口,所以你的机器上
  没有需要暴露或加防火墙的监听器。

如果你自建中继,可用 `NEVOFLUX_RELAY_URL` 覆盖中继地址(默认
`wss://relay.nevoflux.app`)。

## 无头容器

*自 v0.3.14 起包含在发行版中。* 容器可以在完全没有桌面的情况下由手机驱动:
`nevoflux-agent --remote-control` 会运行一个不提供任何 HTTP 接口的控制端,并把连接链接和配对码
打印到日志中;随附的 Compose 文件中有对应的 `remote` 服务。容器可以自行登录
(`nevoflux-agent account login`,或通过 `NEVOFLUX_SERVICE_TOKEN` 注入令牌),它的模式与执行
档位在启动时即固定 —— 永远无法从手机上更改。具体配置见
[无头部署(Docker)](/zh/docs/deployment/remote-control)。

## 已知限制

- **智能体的站点规则匹配的是导航的目标地址**,而不是后续点击或填写所落在的页面。一条
  "在某站点操作前先询问"的规则,只会拦住智能体导航到该站点,拦不住它在已位于该站点的
  标签页中的点击。
- **如果有一个无头 NevoFlux 浏览器注册在同一个守护进程上**,它会代替你的桌面浏览器响应
  已配对智能体的调用。
- **实时屏幕共享与点对点路径**不在发行版构建中(见上文)。
