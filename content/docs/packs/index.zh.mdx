**扩展包(Pack)**是 NevoFlux 扩展能力的打包形式 —— 包含[技能](/zh/docs/skills)、
[Canvas 工具](/zh/docs/canvas/tool-whitelist)、用作起步的[知识库](/zh/docs/knowledge-base)
页面,以及一个 [Canvas](/zh/docs/canvas) 仪表盘 —— 通过单个 `pack.toml` 清单安装。一次
安装把所有东西就位,一次卸载又干净地全部移除。

NevoFlux 0.3.16 接受 `pack-protocol/0.1` 与 `pack-protocol/0.2` 两种清单。0.2 新增的
组件改变的是智能体的*行为*,而不是安装了什么,因此安装这类扩展包前值得先弄清楚。

## 一个扩展包能打包什么

| 组件 | 它带来什么 | 落地位置 |
|---|---|---|
| **技能** | 可复用的智能体能力 | `~/.config/nevoflux/skills/` |
| **Canvas 工具** | 白名单中的命令 / 内部工具 | `~/.config/nevoflux/canvas-tools/` |
| **种子页面** | 可供你编辑的知识库起步页 | GBrain(仅当不存在时写入) |
| **仪表盘** | 一个常驻的 Canvas 微应用 | 我的 Canvas |

每个组件都是可选的 —— 扩展包可以只带其中任意子集。

### 0.2 扩展包还能做什么

| 组件 | 作用 | 何时生效 |
|---|---|---|
| **站点规则** | 在匹配的网站上拒绝某个工具,或先询问你 —— 例如在你的银行网站上任何点击前都先询问 | 扩展包激活期间;若声明为 `installed` 则始终生效 |
| **钩子** | 一段 WebAssembly 检查,可在工具调用运行前拒绝它或要求询问 | 扩展包激活期间;若为 `installed` 则始终生效 |
| **提示词替换** | 允许智能体代表该扩展包替换自己的系统提示词 | 仅在扩展包激活期间 |
| **仪表盘能力** | 扩展包仪表盘可使用的浏览器操作与守护进程命令;未声明的一概得不到 | 仪表盘运行时 |

站点规则和钩子只能让智能体**更严格** —— 扩展包没有任何办法放行你的
[Agent execution 档位](/zh/docs/settings/general#agent-execution-权限档位)不允许的操作。
提示词替换是其中威力最大的一项:声明为 `full` 的扩展包在激活期间可以替换智能体的全部指令。
权限检查本身写在代码里,而不在提示词里,因此不受影响。

### 激活的扩展包

安装扩展包后,它的技能在任何地方都可用。而它的 active 作用域部分 —— 作用域为 `active` 的
站点规则、钩子和提示词替换 —— 只有在智能体**激活**该扩展包(`pack_activate`)后才生效;当你
的目标与扩展包的用途相符时,智能体会去激活它。可以同时激活多个扩展包。只有 0.2 扩展包可以
被激活。

激活只存在于发起它的那次运行及其派生的子智能体中,绝不会带到另一个对话。当智能体想停用一个
正在约束它的扩展包时,必须**先询问你** —— 智能体不能自己解除施加在自己身上的限制 —— 而在
无人值守的循环或定时任务中,它根本做不到。

## 平台为你保证什么

扩展包作者只写声明和文件;守护进程负责*如何*安装与卸载。因此你得到:

- **事务性安装** —— 任一步骤失败,已完成的操作全部回滚。
- **幂等** —— 重复安装同一版本是空操作;种子页面仅当不存在时写入;仪表盘按固定 id 更新。
- **路径安全** —— 文件只会落在白名单扩展目录中,清单无法越界。
- **凭据驱动的干净卸载** —— 平台精确记录它放置了什么,并恰好逆向移除。**除非你明确要求
  清除数据,否则绝不删除你的知识库数据**,并会跳过你安装后已编辑过的文件。

## 安装与管理扩展包

三种方式:**设置 → Packs** 面板、**安装链接**,或命令行。

### 设置 → Packs

[设置 → Packs](/zh/docs/settings/packs) 列出已安装的扩展包,并支持从本地 `pack.toml` 路径
或 **GitHub 源**安装。远程源在写入任何文件前会先经过**检视 → 预览 → 确认**流程。每行都有
**更新**与**卸载**操作,并提供一个**默认关闭**的“同时删除该扩展包的数据”选项。

预览会列出扩展包的技能、Canvas 工具及其运行的二进制、种子页面、仪表盘,以及仪表盘声明的
守护进程命令。它**目前还不会显示** 0.2 扩展包的站点规则、钩子或提示词替换模式 —— 安装你尚不
信任的扩展包之前,请阅读其 `pack.toml` 中的 `[[components.tool_policy]]`、
`[components.hooks]` 和 `[components.prompt]` 部分。

### 安装链接(packhub)

扩展包可以通过一个深链接从任何地方一键发起安装 —— 网站、README,或 packhub 目录:

```
nevoflux://pack-install?src=<github-源>
```

`<github-源>` **仅支持 GitHub**:简写 `github:owner/repo[/sub][@ref]`,或一个
`https://github.com/owner/repo[/tree/ref/sub]` 链接。点击该链接会打开一个专用安装页,运行
与 设置 → Packs 相同的**检视 → 预览 → 确认**流程 —— 预览内容、标记其中携带的工具二进制、
对会阻止安装的策略违规项给出拦截,并要求你明确点击 **Install** 后才会写入(已安装的扩展包
会改为显示**更新** / **重装**)。链接只能*发起*安装 —— 绝不会静默执行。

```
nevoflux://pack-install?src=github:owner/repo
nevoflux://pack-install?src=github:owner/repo@v1.0.0
nevoflux://pack-install?src=https://github.com/owner/repo
```

钉一个 `@ref`(标签或提交)可获得可复现的安装。在网页上放一个安装按钮:

```html
<a href="nevoflux://pack-install?src=github:owner/repo@v1.0.0">在 NevoFlux 中安装</a>
```

### 命令行

命令行需要守护进程在运行:

```bash
nevoflux pack validate  <path/to/pack.toml>   # 干跑能力检查,不写入
nevoflux pack install   <path/to/pack.toml> [--force]
nevoflux pack list                            # 已安装的扩展包
nevoflux pack status    <name>                # 版本、组件数量、依赖
nevoflux pack update    <path/to/pack.toml>
nevoflux pack uninstall <name> [--purge-data] [--force]
```
